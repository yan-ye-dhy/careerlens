### week 1/day 3

### week 1/day 4

今天实现了 CareerLens 的命令行入口。用户可以在命令中提供原始 JD 路径和输出路径；程序读取文本，调用已有的清洗函数，再将结果写入新文件。

#### 文件与模块职责

- `cleaner.py` 只接收字符串、执行清洗并返回新字符串，不读写文件。
- `cli.py` 负责命令行参数、文件读写、输出目录创建、异常提示和退出码，并复用 `cleaner.py` 中的 `clean_jd()`。
- `data/raw/` 保存脱敏原始数据，`data/processed/` 保存程序生成的清洗结果。程序不覆盖原始 JD。

#### 今天学习的语法和行为

1. `sys.argv` 是命令行参数列表：第 0 项是程序或模块标识，后续项是用户提供的参数。
2. `python3 -m careerlens.cli` 会按模块名找到并运行 `cli.py`；`python3 -c` 则直接运行命令行中的一小段 Python 代码。
3. `if __name__ == "__main__":` 使 CLI 在被当作程序运行时调用 `main()`，但被其他代码导入时不会立即读文件或退出。
4. `with open(..., "r", encoding="utf-8")` 按 UTF-8 读取文本；`read()` 返回字符串。
5. `with open(..., "w", encoding="utf-8")` 写入文本；`"w"` 会创建不存在的文件，也会清空已存在文件的原内容。`write()` 不会自动加换行。
6. `Path(...).parent.mkdir(parents=True, exist_ok=True)` 可在写入前确保输出文件的父目录存在。
7. `try` / `except FileNotFoundError` 将“输入文件不存在”转换为清楚的用户错误，避免普通用户看到 traceback。成功返回退出码 `0`，失败返回非零值。

#### 今天最有价值的错误和新认识

- `try` 和 `with` 是两层语句，需要写成 `try:` 后再缩进 `with open(...)`，不能写成 `try with`。
- `open()` 的编码参数名是 `encoding`，不是 `coding`。
- 导入函数的语法顺序是 `from careerlens.cleaner import clean_jd`。
- 交互式解释器中输入 `with` 等缩进代码块时，需要用空行结束代码块。
- `sha256sum` 可以生成文件内容的哈希指纹。原始 JD 在 CLI 运行前后哈希一致，说明原始文件没有被改动。

### week 1/day 5

今天学习了 pytest 和测试思维，为 Day 3 的三个文本清洗函数编写了 8 个自动化测试。测试覆盖连续空格、Tab 与换行、首尾空白、多个空行、空字符串、纯空白字符串、中英文与标点混合，以及 `clean_jd()` 的幂等性。

#### 测试思维与项目结构

- 一个测试用例可以按“准备输入—调用函数得到实际结果—与预期结果比较”来组织。
- `print()` 只展示内容；`assert` 会判断条件是否成立，并在条件不成立时让测试失败。
- 正常情况检查常规输入，边界情况检查空字符串或纯空白等边缘输入，异常情况检查读取不存在文件等无法正常完成的操作。
- `.venv/` 是项目本地的隔离环境，不属于源码，也不应提交到 Git。
- `requirements-dev.txt` 记录 pytest 及其依赖版本，便于其他人重建开发和测试环境。
- `tests/test_cleaner.py` 与 `src/careerlens/cleaner.py` 分离：前者检查行为，后者实现功能。

#### pytest 的使用

1. pytest 按命名规则自动发现测试：测试文件和测试函数都使用 `test_` 前缀。
2. `PYTHONPATH=src python -m pytest -v` 从 `src/` 查找项目包并运行测试；`-v` 会逐项显示测试名称和结果。
3. 首轮运行收集到 8 个测试，结果为 `8 passed`。
4. 测试名称应描述被检查的规则，这样失败报告能直接帮助定位问题。

#### 今天最有价值的错误和新认识

- 第一次创建 `.venv/` 时，因为 Ubuntu 缺少 `python3.12-venv` 和 `ensurepip` 而失败；安装系统包、删除不完整环境并重新创建后成功。
- 故意把清洗函数的单空格连接改成双空格后，测试结果从 `8 passed` 变成 `4 failed`。失败报告显示预期值 `'AI Agent'` 与实际值 `'AI  Agent'` 的差异；恢复实现后重新得到 `8 passed`。
- 只有依赖被破坏规则的测试会失败，其他测试仍可通过，因此需要用多条测试覆盖不同性质。
- 幂等性通过只能说明结果再次处理后不再变化，不能证明结果本身正确；一个稳定的错误结果也可能满足幂等性。

### Git 的核心认识

1. 工作区保存当前文件；`git add` 把指定版本放入暂存区；`git commit` 把暂存快照写入本地历史；只有 `git push` 才上传远程仓库。
2. 已暂存文件再次修改后会显示 `AM`：左侧 `A` 表示暂存区已有新增版本，右侧 `M` 表示工作区还有未暂存修改。再次 `git add` 才会更新暂存快照。
3. `.gitignore` 不删除本机文件，只阻止匹配的未跟踪内容被误纳入版本控制。
4. `.venv/` 可由依赖清单重建，Python 与 pytest 缓存由工具生成，`data/processed/` 可由 CLI 重建，`tmp/` 可能含个人材料，因此都不提交。
5. 使用 `git diff --cached --stat` 检查暂存摘要，使用 `git diff --cached --check` 找到并修复了 `day2_skill_stats.py` 的行尾多余空格。
6. 使用 `git show --stat --oneline HEAD` 查看最新提交；长输出进入 `less` 后可用空格翻页、`b` 返回上一页、`q` 退出。

### 今天最有价值的错误和新认识

- `cat` 输出的文件末尾没有换行时，Shell 提示符会接在文本后面；长行发生视觉折行时可用 `Ctrl + C` 取消输错且尚未执行的命令。
- 选项含义取决于命令：`rm -r` 中的 `-r` 表示递归，`pip install -r` 中表示读取依赖清单，`test -f` 中的 `-f` 表示检查普通文件。
- CLI 是 Command-Line Interface：用户通过终端命令提供参数，`cli.py` 协调文件和功能模块。
