# CareerLens Week 3 学习计划

## 当前状态

- 主题：Python 工程衔接、批量岗位处理与可替换提取器
- 状态：Day 1–Day 7 已完成，Week 3 已验收
- 前置成果：Week 2 固定格式 JD 解析、`JobPosting` 数据模型、JSON CLI 与 19 个自动化测试

## 本周定位

Week 3 是最后一周集中学习 Python 与基本工程能力。本周不继续把固定解析器包装成最终智能能力，而是建设 LLM 同样需要的批量读取、错误隔离、统计、测试和可替换处理流程。

```text
多份 JD 文件
→ 批量读取
→ 逐份清洗
→ 可替换的岗位提取函数
→ 成功岗位与失败记录
→ 技能统计
→ JSON 报告
```

Week 3 完成后，Week 4 Day 1 开始学习大模型基础与第一次 LLM 结构化提取。固定规则解析器将作为可测试的基线和回退方案，而不是通用 JD 理解的最终实现。

## 本周目标

完成后应当能够：

- 使用推导式、排序和计数工具整理岗位数据。
- 使用 `pathlib` 遍历目录并批量读取 UTF-8 文本文件。
- 让单个文件失败时不影响其他文件继续处理，并保存清楚的失败原因。
- 理解函数可以作为参数传递，并用它建立可替换的提取步骤。
- 使用 pytest 参数化与临时目录测试多组输入和文件流程。
- 使用 `argparse` 代替手工判断命令行参数数量。
- 从命令行批量生成岗位列表、失败记录和技能统计 JSON。
- 解释固定解析器以后如何替换为 LLM 提取器，而下游统计与保存逻辑无需重写。

## 本周项目边界

本周不引入：

- LLM API、Prompt 或 API Key。
- FastAPI、数据库或 Web 页面。
- RAG、Embedding 或 Agent。
- 并发、异步或复杂设计模式。
- 为追求形式而增加抽象基类或大型框架。

Week 3 仍使用固定格式样例验证批量处理流程，但不扩展成“支持任意 JD”的规则集合。

## 候选项目结构

以下只是候选结构，每个文件都要在对应学习日理解职责后，由学习者创建或明确授权 AI 创建：

```text
careerlens/
├── src/careerlens/
│   ├── analysis.py            # 岗位技能统计与排序
│   ├── batch.py               # 多文件读取、处理和失败记录
│   └── cli.py                 # Day 6 扩展批量命令
├── tests/
│   ├── test_analysis.py
│   └── test_batch.py
└── practice/

```

`analysis` 是“分析”，负责从结构化岗位中计算统计结果；`batch` 是“批次”，表示一次处理一组文件。实际文件和函数名在当天设计输入输出后再确定。

## 每日安排

### Day 1：推导式、排序与技能计数

- 学习列表/字典推导式的输入、筛选和输出类型。
- 学习 `sorted()`、`key` 和排序方向。
- 学习 `collections.Counter`，理解它与 Week 1 手写字典计数的关系。
- 从多份 `JobPosting` 中统计技能出现次数并生成稳定排名。
- 在决定模块职责后，完成技能统计的最小实现和测试。

### Day 2：目录与批量文件读取

- 学习 `Path` 的目录、文件和后缀判断。
- 学习遍历指定目录中的 `.txt` 文件，并保持确定顺序。
- 批量读取多份 UTF-8 脱敏 JD，不修改原文件。
- 明确空目录、非目录和混入其他文件时的行为。

### Day 3：批量处理与失败隔离

- 区分“整个命令无法开始”和“某一份输入处理失败”。
- 对每份文本依次清洗、解析，并分别保存成功结果或失败原因。
- 保证一份 JD 格式错误时，其他合法 JD 仍能得到结果。
- 设计简单、可序列化的批量报告结构。

### Day 4：函数作为参数与可替换提取器

- 理解函数名本身也可以作为对象保存和传递。
- 让批量流程接收一个“文本到 `JobPosting`”的提取函数。
- 当前传入固定规则解析函数，验证行为不变。
- 画出 Week 4 将固定提取函数替换为 LLM 提取函数后的数据流。
- 不提前实现 LLM，也不引入复杂抽象类。

### Day 5：参数化测试与临时目录

- 学习 `pytest.mark.parametrize`：让同一个测试运行多组输入。
- 学习 `tmp_path`：在 pytest 提供的临时目录中创建测试文件。
- 测试多文件成功、单文件失败、空目录和非文本文件等行为。
- 继续练习从失败报告区分测试数据、预期值和实际结果。

### Day 6：`argparse` 与批量 CLI

- 学习 `argparse`（argument parser，命令行参数解析器）的基本职责。
- 用明确选项表达文本清洗、单份 JSON 和批量 JSON 三种模式。
- 保留现有成功路径，避免无意破坏 Week 1 和 Week 2 行为。
- 输出包含成功岗位、失败记录和技能统计的 UTF-8 JSON。
- 运行完整回归测试并手动验证三种 CLI 路径。

### Day 7：闭卷复现与周复盘

- 不查看生产批量模块，复现简化的多岗位技能统计或批处理函数。
- 口述文件、文本、提取函数、数据模型、统计结果和 JSON 的数据流。
- 解释单文件失败为什么不应总是终止整个批次。
- 解释 Week 4 接入 LLM 时哪些模块会变化、哪些模块可以复用。
- 按停止条件验收并形成 Week 3 周总结。

## Week 2 能力巩固规则

在本周真实任务中自然检查，不单独安排语法补强课：

- 字符串方法的返回值是否被正确保存。
- 独立函数与实例方法的调用方式是否混淆。
- `@dataclass`、类型标注和赋值符号是否正确。
- 局部变量、模块常量、函数和文件名是否符合语境。
- Shell 命令、Python REPL 语句和项目文件代码是否区分清楚。
- 相对路径相对于哪个当前目录解析。

若同类错误反复出现并影响核心实现，再安排针对性最小练习。

## Week 3 停止条件

满足以下条件才进入 Week 4：

- 能从指定目录读取多份 `.txt` 文件，并说明返回数据的类型。
- 能对多份岗位统计技能频率并生成可预测的排序结果。
- 能让一个非法文件不阻止其他文件处理，并输出具体失败原因。
- 能解释函数作为参数传递的最小例子及其在提取器替换中的用途。
- 能阅读并编写至少一个参数化测试和一个 `tmp_path` 文件测试。
- 能使用 CLI 生成一份批量 JSON 报告。
- 现有文本清洗与单份 JSON 功能继续通过回归验证。
- 能明确说明固定解析与 LLM 提取的职责边界。
- 能随机口述本周筛选后的核心面试问题，并结合 CareerLens 举例。
